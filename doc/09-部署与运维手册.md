# 09 部署与运维手册

## 1. 构建命令

```bash
mvn clean package -DskipTests
```

## 2. 常见部署方式

参考当前仓库已有说明，典型流程如下：

```bash
cd /www/wwwroot/novel-plus
mvn clean package -DskipTests
systemctl restart novel-front
systemctl restart novel-admin
```

## 3. 配置位置

- 根配置：`config/shardingsphere-jdbc.yml`
- 前台：`novel-front/src/main/resources/application.yml`
- 后台：`novel-admin/src/main/resources/application.yml`
- 爬虫：`novel-crawl/src/main/resources/application.yml`

## 4. 数据库初始化

首次安装：

- 执行 `doc/sql/novel_plus.sql` 或
- 执行 `doc/sql/novel_plus_data.sql` 中对应 SQL

版本升级：

- 按日期顺序执行当前版本之后新增的增量 SQL

## 5. 当前运维关注点

- 后台依赖 `config/shardingsphere-jdbc.yml`
- 前台和爬虫采用独立服务端口
- 模板资源会在构建中复制
- 配置中存在示例敏感信息，正式环境必须替换

## 6. 本机开发启动要求

- 本机开发允许独立启动 `novel-front`、`novel-admin`、`novel-crawl`
- 本机开发使用的数据库、Redis、第三方密钥等敏感信息，不得写入受版本控制的文件
- 必须通过以下方式之一覆盖：
  - 本地私有配置文件
  - 环境变量
  - JVM 启动参数

## 7. 本机私有配置目录

仓库已约定以下目录和文件用于本机私有配置，并通过 `.gitignore` 忽略：

- `config/local/`
- `config/*.local.yml`
- `config/*.local.yaml`

## 8. ShardingSphere 本地配置

后台默认读取：

- `config/shardingsphere-jdbc.yml`

本机开发可通过环境变量指定私有配置文件：

```bash
export SHARDING_CONFIG_PATH=/绝对路径/novel-plus/config/local/shardingsphere-jdbc.local.yml
```

私有配置文件中填写你本机自己的数据库连接信息，但该文件不能提交到仓库。

## 9. Spring 配置覆盖建议

前台、后台、爬虫的本机敏感配置，建议通过环境变量或启动参数覆盖，例如：

```bash
--spring.data.redis.password=本机私有值
--spring.redis.password=本机私有值
```

如果需要覆盖数据库、端口、上传目录、模板目录，也优先使用本地私有配置或启动参数。

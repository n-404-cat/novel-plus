# 05 接口设计

## 1. 说明

本文档记录当前系统的主要接口域，作为后续接口变更同步入口。

## 2. 前台接口

### 2.1 小说接口 `book/*`

主要能力：

- 首页推荐位
- 点击榜、新书榜、更新榜
- 分类查询
- 搜索分页
- 详情查询
- 排行查询
- 点击数更新
- 章节相关信息查询
- 评论、回复、点赞、点踩

### 2.2 用户接口 `user/*`

主要能力：

- 登录
- 注册
- Token 刷新
- 书架查询与维护
- 阅读历史查询与维护
- 用户反馈
- 用户信息查询与修改
- 密码修改
- 评论查询
- 章节购买

### 2.3 作者接口 `author/*`

主要能力：

- 笔名校验
- 作品分页查询
- 发书
- 更新书籍状态
- 发章节
- 查询章节内容
- 修改章节内容
- 更新封面
- 日/月收益
- AI 生图
- AI 扩写、缩写、续写、润色

### 2.4 其他前台接口

- `news/*`
- `friendLink/*`
- `cache/*`
- `pay/*`
- `file/*`

## 3. 后台接口

后台接口主要以 `/novel/*` 为前缀，覆盖：

- 小说管理
- 分类管理
- 章节管理
- 评论管理
- 用户管理
- 作家管理
- 新闻管理
- 友情链接管理
- 支付管理
- 统计管理
- 网站信息管理

其中网站信息管理已作为站点基础配置入口，后续承载：

- 站点名称
- 域名
- SEO 信息
- Logo
- 前台模板名称

当前与 `R-029` 直接相关的接口补充如下：

- 后台网站信息保存接口：`/novel/websiteInfo/update`
- 后台网站配置缓存清理接口：`/novel/websiteInfo/clearCache`
- 前台缓存刷新接口继续保留 `cache/refresh/*`，供后台转调或运维兜底使用

当前与 `R-030` 直接相关的接口现状如下：

- 前台发起支付宝支付：`POST /pay/aliPay`
- 前台支付宝异步通知：`/pay/aliPay/notify`
- 后台当前仅提供充值订单查询与详情，不提供支付渠道配置维护接口

`R-030` 后续需要补齐的接口方向：

- 后台支付配置页面：`GET /novel/paymentConfig`

`R-031` 个人支付兼容方案需要补充的接口：

- 前台上传支付凭证：`POST /file/upload`（复用现有文件上传或新建凭证上传接口）
- 前台提交个人支付凭证记录：`POST /pay/personalPay`
- 后台充值审核列表页面：`GET /novel/orderPayAudit`
- 后台充值审核数据接口：`GET /novel/orderPayAudit/list`
- 后台充值审核操作接口：`POST /novel/orderPayAudit/audit`
- 后台支付配置保存接口：`POST /novel/paymentConfig/update`
- 后台支付配置缓存清理接口：`POST /novel/paymentConfig/clearCache`
- 后台全站缓存管理页接口：
  - `GET /novel/cacheManage`
  - `GET /novel/cacheManage/items`
  - `POST /novel/cacheManage/clear`
  - 入参：`cacheCodes[]`
  - 出参：本次清理的缓存项数量、实际删除的 Redis key 数量、已执行的缓存项编码列表
- 首期页面与接口默认维护 `ALIPAY` 单渠道，参数包含应用 ID、公钥、私钥、通知地址、回跳地址、网关、签名类型、字符集、环境、启停状态
- 前台支付发起接口仍沿用 `POST /pay/aliPay`，但内部配置来源从静态 `AlipayProperties` 切换为“数据库配置优先 + 本地配置兜底”
- 前台异步通知接口仍沿用 `/pay/aliPay/notify`，签名验签配置同样改为运行期动态读取

当前与 `R-032` 直接相关的后台接口现状如下：

- 已有小说管理接口：`/novel/book/*`
- 已有目录管理接口：`/novel/bookIndex/*`
- 已有正文管理接口：`/novel/bookContent/*`

`R-032` 后续需要补齐的接口方向：

- 小说审核详情聚合接口（一本小说下聚合基础信息、目录、正文）
- 小说审核操作接口（通过/驳回/发布）
- 审核意见记录查询接口
- 小说审核状态流转接口

当前与 `R-041` 直接相关的后台接口如下：

- 新闻采集页面：`GET /novel/news/crawl`
- 内置新闻采集源列表：`GET /novel/news/crawl/sources`
- 新闻采集预览：`POST /novel/news/crawl/preview`
  - 入参：`sourceCode`、`url`
  - 出参：采集源、源地址、标题、正文 HTML
  - 行为：正文 HTML 保留白名单标签；正文内图片尽量下载到后台上传目录并替换为 `/files/` 站内访问路径，下载失败时保留远程图片地址，不中断整篇新闻采集
- 新闻采集保存：`POST /novel/news/crawl/save`
  - 入参：`sourceCode`、`url`、`catId`、`catName`、`status`
  - 出参：采集结果与入库新闻 ID
  - 行为：保存成功后清理首页新闻缓存 `indexNewsKey`

当前与 `R-043` 直接相关的接口如下：

- 后台公告管理页面：`GET /novel/announcement`
- 后台公告列表：`GET /novel/announcement/list`
- 后台公告新增页面：`GET /novel/announcement/add`
- 后台公告编辑页面：`GET /novel/announcement/edit/{id}`
- 后台公告详情页面：`GET /novel/announcement/detail/{id}`
- 后台公告保存：`POST /novel/announcement/save`
- 后台公告修改：`POST /novel/announcement/update`
- 后台公告删除：`POST /novel/announcement/remove`
- 后台公告批量删除：`POST /novel/announcement/batchRemove`
- 前台首页滚动公告：`GET /announcement/rolling`
- 前台弹窗公告：`GET /announcement/popup`
- 前台右下角公告：`GET /announcement/corner`
- 前台公告分页列表：`GET /announcement/listByPage`
- 前台公告详情页：`GET /about/announcementInfo-{announcementId}.html`

弹窗和右下角公告的关闭策略由前端根据 `closeMode` 写入浏览器 `localStorage`；`closeMode=1` 表示关闭后永不提示，`closeMode=2` 表示本次关闭、下次打开重新提示。

## 4. 爬虫接口

主要能力：

- 新增爬虫源
- 爬虫源分页查询
- 获取爬虫源详情
- 规则测试
- 更新爬虫源
- 开启或关闭爬虫
- 新增单本采集任务
- 单本采集任务分页查询
- 删除采集任务
- 查询任务进度

## 5. 后续维护要求

- 新增、修改、删除接口时，必须同步更新本文件
- 接口参数或返回结构发生变化时，必须记录变更点

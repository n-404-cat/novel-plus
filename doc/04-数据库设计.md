`website_info` 当前除基础站点信息外，还承担：

`order_pay` 当前仅覆盖标准充值订单基础字段：

- 商户订单号
- 第三方交易号
- 支付渠道
- 交易金额
- 用户 ID
- 支付状态

这意味着它暂时不足以独立承载 `R-031` 个人支付兼容方案，后续至少需要补充或新增：

- 支付凭证图片/上传记录
- 付款账号或付款备注
- 识别状态与识别结果
- 审核状态、审核人、审核时间
- 审核意见、失败原因、幂等去重信息

`R-030` 新增独立支付配置表 `payment_config`，与 `website_info` 分离，当前字段规划如下：

- `id`：主键
- `channel_code`：支付渠道编码，如 `ALIPAY`、`ALIPAY_PERSONAL`
- `channel_name`：支付渠道名称，便于后台展示
- `app_id`：应用 ID
- `public_key`：支付宝公钥
- `private_key`：商户私钥
- `notify_url`：异步通知地址
- `return_url`：支付完成回跳地址
- `gateway_url`：支付宝网关地址
- `sign_type`：签名算法，默认 `RSA2`
- `charset`：字符集，默认 `utf-8`
- `pay_environment`：运行环境标记，例如 `sandbox`、`production`
- `enabled`：启停状态，`1` 表示启用，`0` 表示停用
- `remark`：后台备注
- `qr_code_url`：个人收款二维码图片地址（为 `R-031` 新增）
- `create_time` / `create_user_id` / `update_time` / `update_user_id`：审计字段

该表设计目标：

- 为后台配置支付参数提供独立承载结构
- 为后续 `R-031` 个人支付、更多支付渠道接入预留 `channel_code` 维度
- 允许前台基于渠道编码做缓存读取与即时失效

针对 `R-031` 个人支付兼容方案，新增 `order_pay_audit` 表用于承载凭证与审核数据：

- `id`：主键
- `out_trade_no`：商户订单号，关联 `order_pay` 表
- `voucher_path`：支付凭证图片路径
- `payer_account`：付款账号或备注
- `ocr_result`：OCR 识别结果（如有自动识别）
- `audit_status`：审核状态（0-待审核, 1-审核通过, 2-审核拒绝）
- `audit_user_id`：审核人ID
- `audit_time`：审核时间
- `audit_remark`：审核意见/拒绝原因
- `create_time` / `update_time`：创建与更新时间

## 4. R-043 公告表设计

`announcement` 用于承载文章公告、首页滚动公告、弹窗公告、右下角公告：

- `id`：主键
- `title`：公告标题
- `content`：公告正文 HTML
- `type`：公告类型，`1` 文章公告、`2` 首页滚动、`3` 弹窗、`4` 右下角
- `status`：状态，`0` 下架、`1` 上架
- `close_mode`：关闭策略，`1` 关闭后永不提示、`2` 下次打开重新提示
- `sort`：排序值，越大越靠前
- `start_time` / `end_time`：展示时间范围
- `create_time` / `create_user_id` / `update_time` / `update_user_id`：审计字段

首页滚动公告优先读取 `type=2` 的公告；未配置滚动公告时，回退读取 `type=1` 的最新文章公告。

## 5. 后续维护要求

- 新增表或字段时，必须同步更新本文件
- 数据结构变更必须补增量 SQL
- 涉及分表策略调整时，必须同步更新部署与配置文档

## 6. R-044 电子书表设计

`ebook` 用于管理 PDF、TXT、EPUB、AZW3、MOBI 等文件型电子书：

- `id`：主键
- `book_name`：书名
- `author_name`：作者
- `isbn`：ISBN
- `cover_url`：封面地址
- `file_url`：电子书文件地址
- `file_format`：文件格式，统一小写，如 `pdf`、`txt`、`epub`、`azw3`、`mobi`
- `file_size`：文件大小，单位字节
- `intro`：简介
- `author_intro`：作者简介
- `status`：状态，`0` 下架、`1` 上架
- `sort`：排序值，越大越靠前
- `create_time` / `create_user_id` / `update_time` / `update_user_id`：审计字段

第一阶段不保存转换产物路径。后续接入 Calibre 或其他转换服务时，可新增 `read_url`、`convert_status`、`convert_message` 等字段。

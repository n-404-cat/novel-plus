### 2.4 运营域

- `news`
- `news_category`
- `friend_link`
- `order_pay`
- `website_info`

`website_info` 当前除基础站点信息外，还承担：

- 网站 Logo 配置
- 前台模板名称配置

`order_pay` 当前仅覆盖标准充值订单基础字段：

- 商户订单号
- 第三方交易号
- 支付渠道
- 交易金额
- 用户 ID
- 支付状态

这意味着它暂时不足以独立承载 `R-031` 个人支付兼容方案，后续至少需要补充或新增：

- 支付凭证图片/上传记录
- 付款账号或付款备注
- 识别状态与识别结果
- 审核状态、审核人、审核时间
- 审核意见、失败原因、幂等去重信息

`R-030` 新增独立支付配置表 `payment_config`，与 `website_info` 分离，当前字段规划如下：

- `id`：主键
- `channel_code`：支付渠道编码，首期固定为 `ALIPAY`
- `channel_name`：支付渠道名称，便于后台展示
- `app_id`：应用 ID
- `public_key`：支付宝公钥
- `private_key`：商户私钥
- `notify_url`：异步通知地址
- `return_url`：支付完成回跳地址
- `gateway_url`：支付宝网关地址
- `sign_type`：签名算法，默认 `RSA2`
- `charset`：字符集，默认 `utf-8`
- `pay_environment`：运行环境标记，例如 `sandbox`、`production`
- `enabled`：启停状态，`1` 表示启用，`0` 表示停用
- `remark`：后台备注
- `create_time` / `create_user_id` / `update_time` / `update_user_id`：审计字段

该表设计目标：

- 为后台配置支付参数提供独立承载结构
- 为后续 `R-031` 个人支付、更多支付渠道接入预留 `channel_code` 维度
- 允许前台基于渠道编码做缓存读取与即时失效

## 3. 设计特征

- 章节内容存在独立内容表与分表
- 后台通过 ShardingSphere JDBC 访问分片配置
- SQL 交付同时覆盖初始化与升级场景

## 4. 后续维护要求

- 新增表或字段时，必须同步更新本文件
- 数据结构变更必须补增量 SQL
- 涉及分表策略调整时，必须同步更新部署与配置文档

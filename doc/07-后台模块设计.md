# 07 后台模块设计

## 1. 模块职责

`novel-admin` 负责平台运营、内容管理与系统管理。

## 2. 主要功能

- 小说管理
- 分类管理
- 章节管理
- 评论管理
- 用户管理
- 作家管理
- 支付管理
- 新闻管理
- 友情链接管理
- 网站配置管理
- 统计管理
- 系统用户、角色、菜单、字典管理
- 代码生成辅助

## 3. 主要入口

- 启动类：`AdminApplication`
- 核心控制器：
  - `BookController`
  - `BookContentController`
  - `BookIndexController`
  - `BookSettingController`
  - `AuthorController`
  - `UserController`
  - `NewsController`
  - `CategoryController`
  - `PayController`
  - `StatController`

## 4. 技术特征

- 使用 Spring Boot 2.7.x
- 使用 Thymeleaf 渲染后台页面
- 使用 Shiro 做权限控制
- 使用 ShardingSphere JDBC 访问数据源

## 5. 关键实现点

- 后台接口多为页面 CRUD 型接口
- 统计接口作为运营报表入口
- `sys_*` 表支撑后台基础系统能力
- 存在代码生成辅助相关表结构
- `website_info` 已作为站点基础配置入口，后续继续承载模板名称、Logo、支付等站点级配置

## 6. `R-029` 相关设计补充

- 网站信息页除保存站点字段外，还负责维护前台模板名称
- 后台保存网站信息后，不再提示“重启 novel-front 后生效”
- 后台提供站点缓存清理入口，用于清理前台网站信息与模板相关缓存
- 后台在清理缓存失败时需要返回明确错误，避免运营误以为已经生效
- 后台新增统一缓存管理面板，首版覆盖以下 Redis 缓存项：
  - 网站信息与模板缓存：`websiteInfoKey`
  - 支付配置缓存：`paymentConfigKey:*`
  - 首页小说推荐缓存：`indexBookSettingsKey:v2`
  - 首页新闻缓存：`indexNewsKey`
  - 首页友情链接缓存：`indexLinkKey`
  - 首页点击榜缓存：`indexClickBankBookKey`
  - 首页新书榜缓存：`indexNewBookKey`
  - 首页更新榜缓存：`indexUpdateBookKey`
  - 敏感词缓存：`sensitiveWordKey`
  - 测试爬虫规则缓存：`testParse*`
  - 模板模式缓存：`templateDirKey*`
  - 搜索引擎相关缓存：`esLastUpdateTime`、`esTransLock`、`esIsUpdateVisit`
  - 点击增量缓存：`bookAddVisitCount`
  - AI 生成图片缓存：`aiGenPic*`
  - 下载中的小说锁：`book:isDownloading:*`
- 缓存管理面板支持：复选框、多选、全选、反选、按项清理、一键全清，并返回本次实际删除的 key 数量。
- 缓存管理面板交互要求：
  - 默认展示缓存项名称、key 规则、影响范围、缓存类型
  - 支持全选、反选、清空选择
  - 提交后弹出本次清理结果摘要，明确显示删除 key 数量
  - 若某缓存项当前无命中 key，也要提示“未命中”而不是静默成功

## 7. `R-030` 相关设计补充

- 当前后台只有充值订单管理，没有支付渠道配置管理页面
- 当前支付宝参数直接由前台模块配置文件读取，不符合“敏感信息不入库、不入仓”的协作规范
- 第一阶段先清理仓库中的硬编码支付密钥，改为环境变量或本地私有配置覆盖
- 第二阶段新增后台支付配置管理能力，统一维护：
  - 支付渠道类型
  - 应用 ID / 公钥 / 私钥
  - 网关地址
  - 异步通知地址 / 回跳地址
  - 沙箱/生产环境标记
  - 启停状态
- 后台页面首期采用单页配置模式，不做列表页，直接维护 `ALIPAY` 默认配置
- 页面按钮至少包括：
  - 保存并生效
  - 清理支付配置缓存
- 后台保存逻辑需要覆盖：
  - 新记录首次创建
  - 已有 `ALIPAY` 记录的更新
  - 保存后删除 Redis 中对应渠道缓存，确保前台下一次支付请求立即读取新配置

## 8. `R-031` 相关设计补充

- 当前后台只有充值订单列表与详情，没有“支付凭证审核”“人工充值审核”“识别失败复核”入口
- 当前 `order_pay` 只支持标准支付回调成功后直接加余额，不支持“先提交凭证、后识别、再审核”的异步流程
- 后续后台至少需要新增：
  - 个人支付订单审核列表
  - 支付凭证详情页
  - 自动识别结果展示
  - 人工通过/驳回操作
  - 审核日志与充值审计记录

## 9. `R-032` 相关设计补充

- 已在小说管理列表（`book.html`）增加“审核”入口按钮。
- 新增小说审核工作台页面（`audit.html`）：

## 10. `R-041` 后台新闻采集设计补充

- 新闻列表工具栏增加“采集”入口，复用 `novel:news:add` 权限，避免新增菜单权限前页面不可见。
- 采集页支持选择内置源、填写新闻详情页 URL、选择分类与上架状态。
- 第一版内置源由代码常量维护，不写入账号、密码、密钥等敏感配置；后续如需运营维护规则，可迁移为数据库表。
- 后端 `NewsCrawlService` 负责 URL 校验、页面抓取、标题/正文解析、正文 HTML 清洗与入库。
- 正文解析需要尽量保留原文结构，允许 `p/div/br/h1-h6/strong/b/em/i/u/blockquote/ul/ol/li/a/img/table` 等展示类标签。
- 正文图片采集时优先下载到后台上传目录，再替换为 `/files/yyyy/MM/dd/文件名` 形式，保证后台预览与前台详情均访问站内图片；下载失败时保留远程图片地址，避免单张图片失败导致整篇新闻采集失败。
- 安全处理必须移除 `script/style/iframe/object/embed` 等危险标签，过滤 `on*` 事件属性、`javascript:` 链接和非白名单属性。
- 采集保存复用现有 `news` 表与 `NewsService.save`，保存成功后清理首页新闻缓存，保证前台列表可尽快更新。
- 带域名白名单的内置源必须匹配对应域名；通用源只允许 `http/https`，用于临时验证不同新闻详情页结构。

## 11. `R-043` 后台公告管理设计补充

- 公告使用独立 `announcement` 表，不复用新闻表，避免弹窗、右下角、关闭策略等展示属性污染新闻模型。
- 后台公告管理提供列表、新增、编辑、详情、删除、批量删除能力。
- 公告类型包括文章公告、首页滚动公告、弹窗公告、右下角公告。
- 公告状态为上架/下架，前台只读取上架且在展示时间范围内的公告。
- 弹窗和右下角公告支持关闭策略：关闭后永不提示、下次打开重新提示。
- 首页滚动公告优先取滚动类型公告；没有滚动类型公告时回退文章公告最新几条。

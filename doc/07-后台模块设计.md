# 07 后台模块设计

## 1. 模块职责

`novel-admin` 负责平台运营、内容管理与系统管理。

## 2. 主要功能

- 小说管理
- 分类管理
- 章节管理
- 评论管理
- 用户管理
- 作家管理
- 支付管理
- 新闻管理
- 友情链接管理
- 网站配置管理
- 统计管理
- 系统用户、角色、菜单、字典管理
- 代码生成辅助

## 3. 主要入口

- 启动类：`AdminApplication`
- 核心控制器：
  - `BookController`
  - `BookContentController`
  - `BookIndexController`
  - `BookSettingController`
  - `AuthorController`
  - `UserController`
  - `NewsController`
  - `CategoryController`
  - `PayController`
  - `StatController`

## 4. 技术特征

- 使用 Spring Boot 2.7.x
- 使用 Thymeleaf 渲染后台页面
- 使用 Shiro 做权限控制
- 使用 ShardingSphere JDBC 访问数据源

## 5. 关键实现点

- 后台接口多为页面 CRUD 型接口
- 统计接口作为运营报表入口
- `sys_*` 表支撑后台基础系统能力
- 存在代码生成辅助相关表结构
- `website_info` 已作为站点基础配置入口，后续继续承载模板名称、Logo、支付等站点级配置

## 6. `R-029` 相关设计补充

- 网站信息页除保存站点字段外，还负责维护前台模板名称
- 后台保存网站信息后，不再提示“重启 novel-front 后生效”
- 后台提供站点缓存清理入口，用于清理前台网站信息与模板相关缓存
- 后台在清理缓存失败时需要返回明确错误，避免运营误以为已经生效

## 7. `R-030` 相关设计补充

- 当前后台只有充值订单管理，没有支付渠道配置管理页面
- 当前支付宝参数直接由前台模块配置文件读取，不符合“敏感信息不入库、不入仓”的协作规范
- 第一阶段先清理仓库中的硬编码支付密钥，改为环境变量或本地私有配置覆盖
- 第二阶段新增后台支付配置管理能力，统一维护：
  - 支付渠道类型
  - 应用 ID / 公钥 / 私钥
  - 网关地址
  - 异步通知地址 / 回跳地址
  - 沙箱/生产环境标记
  - 启停状态
- 后台页面首期采用单页配置模式，不做列表页，直接维护 `ALIPAY` 默认配置
- 页面按钮至少包括：
  - 保存并生效
  - 清理支付配置缓存
- 后台保存逻辑需要覆盖：
  - 新记录首次创建
  - 已有 `ALIPAY` 记录的更新
  - 保存后删除 Redis 中对应渠道缓存，确保前台下一次支付请求立即读取新配置

## 8. `R-031` 相关设计补充

- 当前后台只有充值订单列表与详情，没有“支付凭证审核”“人工充值审核”“识别失败复核”入口
- 当前 `order_pay` 只支持标准支付回调成功后直接加余额，不支持“先提交凭证、后识别、再审核”的异步流程
- 后续后台至少需要新增：
  - 个人支付订单审核列表
  - 支付凭证详情页
  - 自动识别结果展示
  - 人工通过/驳回操作
  - 审核日志与充值审计记录

## 9. `R-032` 相关设计补充

- 当前后台已有小说、目录、正文的基础 CRUD 与详情查看能力
- 当前缺失的不是“单表明细页”，而是按一本小说串联展示“目录 + 正文 + 基础信息”的审核工作台
- 当前也缺少明确的审核状态流转，例如：草稿、待审核、审核通过、已发布、驳回
- 后续后台至少需要新增：
  - 小说审核工作台页面
  - 章节目录联动正文预览
  - 审核意见记录
  - 审核通过/驳回/发布操作
  - 审核权限与操作日志
